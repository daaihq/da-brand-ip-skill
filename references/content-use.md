# 文章、企业宣传与节日应用

## 背景与语言

全部应用图默认纯白背景，包括封面、正文、公司海报、产品和节日宣传。允许角色、产品和少量必要道具，不铺有色背景或大面积环境。用户明确要求可覆盖。

图中文字跟随文章主要语言；宣传图跟随宣传文案；用户指定语言优先。中文文章用中文，英文文章用英文，不因X平台自动翻译。中英混合时保留名称、代码、缩写及原有品牌标识，按主要叙述语言写标题与说明；双语接近且无法判断才询问。无文字更合适时不强加文案。不得擅自改写原文事实、日期、价格或虚构译名。原文语言与最终图中文字语言分别记录。

三张基础资产仍默认英文标签；这项约束不传播到文章应用。应用图不使用仅接受ASCII的 compose_board.py；选择支持目标文字的图像或排版工具，检查字体缺字、错字及品牌标识。不为生成中文应用图重新创建IP。

## 平台入口

先读文章并解析用户当前指定的平台（包括本轮已明确上下文）。已指定就直接使用，不重复问。未指定时先问：这篇文章准备发布到哪个平台？固定四个选项：①X平台 ②微信公众号 ③小红书 ④其他（可自行输入）。只有三项容量的选项工具无法准确承载时，直接用普通文字展示四项，不删减或合并。得到平台后再生成。用户明确说不限平台／按你建议时可采用通用16:9并说明。

读取 platform-presets.md：先平台、再位置、再尺寸与安全区。公众号通常采用头条封面＋独立正文图，小红书通常采用3:4封面与连续图文页；X需区分Articles长文章与普通帖子／串文，仅当上下文不能判断且需要封面时补问一次。不要把主页横幅当文章封面。其他平台已有表则按表匹配；没有则读取用户规格或询问发布位置，不杜撰官方限制。

多平台请求分别组织版本并统一角色身份；每张记录平台、用途、文字语言、目标尺寸、实际输出尺寸和正文插入点。可以先提取信息，但不得在未知平台时擅自生成整套图。

资产卡模板固定；每一种应用类型选择对应版式，重复生成同一系列时锁定该系列标题区、图框和信息区坐标。不得要求所有海报也排成5动作＋6表情。

## 输入

用户提供完整文章／已定海报文案。完整读取后提取视觉主题、关键事实、发布用途、比例、指定角色和品牌。只提供主题时询问正文或文案；用户新授权补文案时才扩展。创建角色阶段的命名和动作标签不受此限制。

解析当前品牌与角色；存在多个可能品牌且未指定时询问或展示列表，不跨客户猜测。读取已确认干净角色参考，或设计卡中仅左侧主形象区域、规范、风格ID和必要视图，缺资产时请求恢复，不根据记忆重新发明角色。

## 文章

按信息密度选择数量：单观点常为1张；短文1—3张；长文3—5张；用户数量优先。避免机械按字数凑图。可采用操作演示、观点隐喻、前后对比、场景互动。每图解决不同信息点，角色有具体行为。

正文图按平台预设与内容形态选择：X和公众号普通解释图建议16:9，复杂流程可用4:3；小红书连续图文默认统一3:4。封面独立选规格，不强迫所有正文跟封面同尺寸。精确数据图表用可核对的图形工具制作，IP只能作为引导元素。

逐张生成独立图片，报告图名、用途、建议插入的唯一段落／原文锚点。默认不改原文。明确要求插入可写Markdown时保留原件，输出新的含图副本；不要插进句子、代码块或列表中间。网页或不可写稿件只给建议，不能声称已发布或修改。

## 企业、产品和节日

确定这次传播的一个主要信息和角色职责：展示产品、解释流程、欢迎新成员、邀请参加、表达节日祝福等。角色承担动作，不每张都在角落挥手。

产品宣传保留产品实际形状和提供的参数；装饰性产品拟人和真实产品不能混淆。节日只改允许变化的服饰／道具／环境，不改变物种、核心轮廓、主识别色和固定标志。组织需符合已提供的价值观和语气，不自动制造口号、资质或承诺。

用户完整文案中的价格、日期、地点、联系方式和品牌名逐字核对。长段文字、Logo和二维码优先用用户原素材做准确排版；无法准确呈现时交付留白视觉稿与排版说明并指出待完成内容，不假称成品。二维码必须用给定有效内容生成并验证可读，不能依靠生图绘制假的码。

总览模板只用于角色资产；宣传画面仍默认白底，文字跟随宣传文案语言，但不采用5＋6排列。延续角色画风，在白色空间中围绕传播内容设计角色、产品与少量必要物件；更换角色主画风需新版本确认。

## 交付与复用

保存本次主题的图片、所用角色版本、风格ID、文案来源和插入建议到独立应用项目，不覆盖角色基础包。文件按实际生成情况报告。使用默认已确认版本，草稿不能被自动激活。生成图片与发布是分开的；除非另获明确授权，不对外发布。
